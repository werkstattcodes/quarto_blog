# CLAUDE.md — werk.statt.codes blog

Quarto blog (R, tidyverse) about Austrian politics and the {ParlAT} package. These rules apply to this repo only and take precedence over the global `~/.claude/CLAUDE.md` where they differ.

## Scope of changes

- Each post is self-contained. Define helpers (captions, themes, table styling) once inside the post's own `index.qmd`, not in shared files, and do not edit other posts unless asked.
- Posts use `freeze: true`. Only render the post being worked on.
- Files in a post's `data/` folder are generated by the post's chunks and can be deleted and recreated.

## Writing

- Write R package names in curly braces, e.g. `{ParlAT}`, `{ellmer}`, in prose and in graph captions. Not in code (`library(ParlAT)`) or in YAML category tags.

## Code style

- Pipe: use the magrittr pipe `%>%`, never `|>`, and never mix both in a post.
- Names: snake_case. Data frames start with `df_` (`df_submissions`), counts with `n_` (`n_chars`), vectors/models/prompts are plain nouns (`extraction_prompt`).
- Prefer stringr over base R and `sprintf()`: `str_c()`, `str_glue()`, `str_pad()`.
- Paths: anchor with `here::i_am()` and build them as `here::here(dir_post, "data", "<file>")`. Do not create extra `dir_*` variables for subfolders.
- Keep code simple. No caching or hashing layers unless asked; save results with `write_rds()` and reload with `read_rds()`.
- Comments explain what a block does (short, one line each); do not narrate history.
- All code chunks are folded (`code-fold: true` in the front matter). Give chunks a `code-summary` when the default "Code" label is not enough.
- Set `eval: false` only where the user asks for it.

## Graph styling (ggplot2)

- All graphs use the same theme as the published voting-patterns posts, defined once per post as `theme_post()` in the setup chunk: `theme_minimal(base_size = 11, base_family = "Noto Sans")`, no minor grid lines and no vertical major grid lines, axis text 9 pt, y-axis title 9 pt `grey30`, legend on top, bold 14 pt title, 10 pt `grey30` subtitle and 8 pt `grey45` caption (both via `ggtext::element_textbox_simple()`, so markdown works). Add post-specific tweaks after it, e.g. `theme_post() + theme(axis.text.x = element_blank())`.
- Title, subtitle and caption are aligned with the **plot**, not the panel (`plot.title.position = "plot"`, `plot.caption.position = "plot"`, set in `theme_post()`). The subtitle follows the title position.
- The subtitle states scale or binning choices (e.g. bin width, log scale). The caption is always present. Text geoms use `family = "Noto Sans"`.
- Figure size: keep Quarto's default (7 × 5 in) and do not set `fig-width`/`fig-height`/`out-width`. Larger figures are scaled down to the page width and make the text too small to read. Wrap long titles with `str_wrap(width = 70)` so they fit. Add `fig-alt` to every graph chunk.
- Every graph carries the caption from the post's `attribution_graph()` (data source, ParlAT, date, author) and every table the source line from `kable_attributed()` (plain tables) or `style_reactable_table()` (reactable). All are defined once in the post's setup chunk. In graph captions the Bluesky name is the Font Awesome icon (set slightly lighter than the text, `#9a9a9a`, because a solid glyph looks heavier): register `_extensions/quarto-ext/fontawesome/assets/webfonts/fa-brands-400.ttf` with `systemfonts::register_font()`, escape URLs in the caption as `https&#58;//` and `www&#46;`, and set `dev: ragg_png` in the post's `knitr: opts_chunk`. Table source lines stay plain text.
- Highlight with `firebrick` against greys.
- Annotate highlighted items with labels and arrows rather than a legend.

## Tables

- Interactive tables use `reactable` with `reactablefmtr`: `compact_table_theme` and `style_reactable_table(title, subtitle)` (title in capitals, subtitle in italics, source footer) are defined in the post's setup chunk, copied from the voting-patterns posts. Typical options: `fullWidth`, `compact`, `highlight`, `outlined`.
- Bars come from `reactablefmtr::data_bars()` in their own column next to the number. Highlight an item with `firebrick` (bar, via `fill_color_ref`) against `grey65`, and a light red row background `#fde0dd` with bold text via `rowStyle`.
- Before reporting a graph as done, render it to a PNG in the scratchpad and look at it. Check labels are not cut off or overlapping.

## LLM steps (ellmer)

- Prompts are written in English. Quotations from German source texts must stay verbatim in German; generated descriptions, group names and definitions are in English.
- Pin the model name in a variable (`extraction_model`, `grouping_model`) and keep prompts in named objects.
